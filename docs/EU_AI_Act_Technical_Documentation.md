## 1. General Description of the AI System

### 1.1 System Identity

**Name:** SEBA — AI Teaching Assistant  
**Version:** 1.0 (April 2026)  
**Intended purpose:** SEBA is an AI-assisted educational platform designed to support teachers and students in understanding and applying Spain's LOMLOE (Ley Orgánica de Modificación de la LOE) curriculum framework. It provides AI-generated practice questions, competency assessments, personalised learning path recommendations, teaching material generation, and a conversational AI assistant (Aina).  
**Deployment context:** Primary and secondary schools in Spain, with particular focus on Catalan-medium education in Catalunya, the Valencian Community, and the Balearic Islands.

### 1.2 Risk Classification

Under Annex III, Category 4 of the EU AI Act, SEBA is classified as a **high-risk AI system** because it:

- Generates assessments of students' competency levels that may influence educational decisions.
- Produces personalised learning path recommendations for individual students.
- Operates in an educational setting involving minors.

This classification triggers the full obligations of Chapter 3 of the EU AI Act, including conformity assessment, technical documentation, human oversight, and registration in the EU database.

### 1.3 AI Models Used

| Model | Provider | Purpose | Hosting |
|---|---|---|---|
| **BSC Salamandra** (via Manus Forge API) | Barcelona Supercomputing Centre | Conversational AI (Aina), content generation, bias detection | EEA (BSC, Barcelona) |
| **Helsinki-NLP/opus-mt-en-es** | University of Helsinki / Hugging Face | EN→ES translation of practice questions | Hugging Face Inference (EEA) |
| **Helsinki-NLP/opus-mt-en-ROMANCE** | University of Helsinki / Hugging Face | EN→CA translation of practice questions | Hugging Face Inference (EEA) |

All models are accessed exclusively via EEA-hosted inference endpoints. No data is transferred to non-EEA jurisdictions.

## 2. Detailed Description of Elements and Development Process

### 2.1 System Architecture

SEBA is a full-stack web application with the following components:

| Layer | Technology | Role |
|---|---|---|
| Frontend | React 19, TypeScript, Tailwind CSS 4 | User interface, i18n (EN/ES/CA + Catalan dialects) |
| API layer | tRPC 11, Express 4 | Type-safe RPC between client and server |
| Database | MySQL / TiDB (EEA-hosted) | Persistent storage of all user and educational data |
| AI inference | BSC Salamandra via Manus Forge API | LLM-based content generation and chat |
| Translation | Hugging Face Inference API (Helsinki-NLP) | Question bank localisation |
| File storage | S3-compatible object storage (EEA) | Teaching material files |

### 2.2 Training Data and Knowledge Base

SEBA does not train any models. It uses pre-trained models provided by BSC and the University of Helsinki. The application's knowledge base consists of:

- **480 LOMLOE practice questions** covering 8 competencies × 3 year groups × 20 questions each, authored by qualified educators and stored in the application database.
- **LOMLOE competency metadata** (descriptions, CEFR alignments, year group mappings) derived from the official BOE publication of LOMLOE (BOE-A-2020-17264) [1].
- **Translation pairs** generated by the Helsinki-NLP models and stored in the `question_translations` table, subject to administrator review before student exposure.

### 2.3 Data Flows

```
Student/Teacher Browser
        │
        ▼
  tRPC API (Express)
        │
        ├── Database (MySQL/TiDB) ← all user data, questions, assessments
        │
        ├── BSC Salamandra API ← chat, content generation, bias detection
        │
        └── Hugging Face API ← question translation (admin-triggered only)
```

No student PII is sent to external AI APIs. Chat messages are sent to the BSC Salamandra API without persistent user identifiers; only the session-scoped conversation history is transmitted.

## 3. Monitoring, Functioning, and Control

### 3.1 Performance Metrics

The following metrics are monitored and available in the Admin Dashboard:

| Metric | Measurement method |
|---|---|
| Question translation coverage (ES/CA) | Count of translated vs. total questions per locale |
| Bias flag rate | Number of AI outputs flagged per 100 chat sessions |
| Grade override rate | Number of teacher overrides per 100 AI assessments |
| Practice session completion rate | Sessions completed vs. started |

### 3.2 Human Oversight Mechanisms

Full details are provided in the HITL Policy (SEBA-GOV-HITL-001). Key mechanisms:

- Teachers can override any AI-generated grade with a mandatory written justification.
- All AI chat responses are scanned by a secondary bias-detection LLM call before delivery.
- Learning path recommendations include a full justification report that teachers must review before sharing with students or parents.
- No AI output is automatically applied to a student's record without a teacher action.

### 3.3 Logging and Audit

| Log type | Storage | Retention |
|---|---|---|
| Grade overrides | `ai_grade_overrides` table | Indefinite (compliance record) |
| Bias flags | `ai_bias_flags` table | 30 days after resolution |
| Learning paths | `ai_learning_paths` table | Indefinite (educational record) |
| Practice sessions | `practice_sessions` table | Capped at 200 most recent per user |
| Admin audit log | `admin_audit_logs` table | 1 year |

## 4. Risk Management System

### 4.1 Identified Risks and Mitigations

| Risk | Severity | Likelihood | Mitigation |
|---|---|---|---|
| AI generates biased assessment of student based on name/gender | High | Low | Bias guard middleware scans every AI output; flags are logged and reviewed by teachers |
| AI learning path recommendation disadvantages students from lower socioeconomic backgrounds | High | Low | Justification report exposes reasoning; teacher must review before sharing; no automatic application |
| Translation errors cause students to learn incorrect curriculum content | Medium | Medium | Admin must manually trigger translations; translations are reviewable before student exposure; English fallback always available |
| AI chat provides factually incorrect LOMLOE information | Medium | Medium | Aina is grounded in the 480-question knowledge base; responses cite competency codes; teachers can flag errors via bias incident system |
| Over-reliance on AI grades by teachers | High | Medium | Grade override requires written reason; audit log is visible to school administrators; HITL policy mandates teacher review |
| Data breach exposing student PII | High | Low | Data minimisation (no unnecessary PII collected); EEA hosting; GDPR-compliant deletion; no PII in bias logs |

### 4.2 Residual Risks

After applying the above mitigations, the following residual risks remain:

- **Model hallucination:** BSC Salamandra may occasionally generate plausible but incorrect LOMLOE references. Mitigation: teachers are instructed to verify AI-generated content against official BOE sources before use.
- **Dialect translation quality:** Catalan dialect variants (Valencian, Balearic) may contain occasional vocabulary errors. Mitigation: administrator review step before student exposure; users can revert to IEC Standard Catalan at any time.
